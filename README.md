## 这是什么

一个**纯前端、零依赖、可离线运行**的手冲滤杯参数化设计工具。

它做三件事，而且每一件都做到能落地：

| | 做什么 | 凭什么可信 |
|---|---|---|
| **算** | 用 Darcy 达西渗流 + 孔口堰流建模粉床出水，算流速、断流时间、萃取均匀度 | 物理公式写死在代码里，不是拍脑袋的经验曲线 |
| **建** | 把「壁部导水槽」**真实建出成实体几何**，而不是画在示意图上 | 导水槽的体积、覆盖率与物理模型的电导口径完全一致 |
| **出** | 导出 STL / 3MF / OBJ，拖进拓竹 Bambu Studio 直接切片 | 每个参数组合都做水密流形 + 定向一致性自检 |

> **一句话**：市面上的滤杯设计工具大多止步于「画个截面」，这个工具从物理模型一路走到 **可交付的打印文件**。

## 功能一览

### 🧪 流道物理模型

咖啡从粉床流到杯底，要穿过一层被压实的咖啡粉 —— 这是个**多孔介质渗流**问题；滤孔本身是**孔口堰流**。两者耦合起来，才决定流速与断流风险。

| 环节 | 做法 |
|---|---|
| 粉床横向汇流 | Darcy 达西定律，等效渗透率随压实度与研磨度变化 |
| 滤孔出流 | Torricelli 孔口堰流 `Q = Cd·A·√(2gh)` |
| 时间推进 | 粉床离散时间步进，**fill → percolate → drain** 三相耦合 |
| 泄压通道 | 壁面 + 滤纸形成的袋腔负压，与驱动水头对抗 |
| 通道电导 | 矩形窄缝 `G = w·h³ / (12·μ·L)` |
| 导水槽收益 | **反事实对照**：把通道整个去掉重算一遍，比较同一水头下的瞬时流量 |

最后一条是这套工具的关键：**页面上的「导水槽使工作点流速提升 65%」不是估计值，而是同一套模型、去掉导水槽后重算出来的差值。**

### 🌀 壁部导水槽（真实几何，不是贴图）

| 形式 | 适用杯型 | 物理作用 | 建出方式 |
|---|---|---|---|
| **螺旋凸肋** | 锥形（只有锥壁才形成袋腔） | 壁面排气泄压，破除密闭袋腔 | 沿壁面盘旋的矩形截面凸条，凸入腔内 |
| **径向铣槽** | 平底 / 直筒（锥底无处可铣） | 底面导流汇流，降低横向汇流阻力 | 铣在底板实体**内部**的径向凹坑 |
| **分段模式** | 锥形 | 沿母线分段，每段可选螺旋 / 直肋 / 光壁 | 逐段建出，接缝处无缝衔接 |

**分段模式为什么必须"贯通"？**

泄压通道沿母线是**串联**的。粉床下方的负压要一路排到杯口，所以总泄压阻力 = 各段阻力之和；**任何一段光壁都会成为瓶颈，把整条排气通路堵死**。页面会在诊断面板里把每段阻力单独列出来。

## 工作原理

### ① 粉床：达西渗流

粉床被视作各向同性的多孔介质。横向汇流阻力由 Darcy 定律给出：

```text
Q = k·A·ΔP / (μ·L)
```

其中等效渗透率 `k` 不是常数 —— 它随压实度与研磨度变化：研磨越细、压得越实，`k` 越小，横向汇流越慢，底部越容易出现"死区"（萃取不均）。

### ② 滤孔：孔口堰流

穿过滤孔的水由孔口出流（Torricelli）控制：

```text
Q = Cd·A·√(2gh)
```

`Cd` 取 0.62 左右。孔径越小、滤孔越少，同样的水头下出流越慢 —— 这是"细粉 + 少孔"容易堵塞的直接原因。

### ③ 泄压：袋腔负压 vs 驱动水头

锥形杯的滤纸会贴合锥壁，形成一个**密闭袋腔**。粉床下方的水要挤出来，就得先把袋子里的空气挤走，于是产生负压 `p_vent`。

这个负压会**抵消**一部分驱动水头：

```text
Q_work = f( H_drive − p_vent )
```

结果就是大家熟悉的"咕噜"断流：闷蒸时粉床吸水膨胀，把袋子里的空气挤走，负压顶住水流。

### ④ 导水槽：把负压泄掉

壁部导水槽的作用，就是在袋腔上开一条**通到大气**的通道，把 `p_vent` 拉回接近 0。

- **螺旋凸肋**：在壁面与滤纸之间撑出一条周向窄缝，泄压路径长（阻力大）但覆盖全壁
- **纵向直肋**：沿母线直通杯口，泄压路径短（阻力小），但覆盖面积有限
- **光壁**：没有通道，只剩滤纸与壁面的贴合缝隙，阻力最大

### ⑤ 反事实对照：这条通道到底值多少

这是整个工具最有说服力的一步：

```
有导水槽  →  跑一遍完整模型  →  Q_with
去掉导水槽 →  跑一遍完整模型  →  Q_without

导水槽收益 = Q_with / Q_without − 1
```

两次计算走的是**完全相同的代码路径**，唯一区别是导水槽的几何参数被置零。所以这个差值是可信的，而不是估算。

## 网格质量保证

导水槽这类几何很容易做出"看着对、切片就炸"的网格。本项目对**每一个**参数组合都做拓扑校验：

| 判据 | 含义 | 为什么重要 |
|---|---|---|
| 开放边 = 0 | 没有裸露的边界 | 切片器会判定为破面 |
| 非流形边 = 0 | 每条无向边恰被 2 个三角形共用 | 边被 3 个以上面共用 = 实体自交 |
| **有向边冲突 = 0** | 每条有向边恰出现 1 次 | **绕序自洽**（见下方说明） |
| 退化三角形 = 0 | 无零面积面 | 会让法线计算除零 |
| 法向一致率 = 100% | 存储法向与叉积同向 | 决定切片器判定内外 |

> **「有向边冲突」这一项是后来补上的。** 原先只看「每条边用 2 次」，会漏掉**绕序自相矛盾**的网格：拓扑上看似闭合，体积却算成好几倍，切片出来是一坨实心疙瘩。这个 bug 真实发生过，且靠肉眼看渲染图完全发现不了。

内置 **16 个校验场景**（6 个预设 + 分段导水槽 / 深浅铣槽 / 粗细螺旋 / 极端锥角 / 中心大孔 / 孔环密集）：

```bash
node tools/check_presets.js     # 6 个内置预设
node tools/check_geometry.js    # 16 个扩展场景
```

## 参数参考

### 杯体几何

| 参数 | 范围 | 说明 |
|---|---|---|
| 杯型 | 锥形 / 平底 / 直筒 | 锥形 = V60、Origami 类；平底 = Kalita、Chemex 类；直筒 = 圆柱段 |
| 上口直径 | 60–180 mm | 杯口内径 |
| 锥角（全角） | 20–80° | 仅锥形。V60 是 60°，Origami 约 45° |
| 底面半径 | 3–45 mm | 仅非直筒。锥形杯会被滤孔外缘顶高 |
| 平底深度 | 0–30 mm | 仅平底 |
| 侧壁倾角 | 2–35° | 仅平底 |
| 直筒高度 | 40–150 mm | 仅直筒 |
| 壁厚 | 0.5–8 mm | **法向**壁厚（斜段自动做水平补偿） |
| 底板厚度 | 1–10 mm | 铣槽模式需留余量：槽底至少 0.6 mm |
| 材质 | PP / PET / 玻璃 / 陶瓷 / 不锈钢 / 钛 | 影响重量与耐热估算 |

### 滤孔布局

| 参数 | 范围 | 说明 |
|---|---|---|
| 布局 | 中心单孔 / 环形均布 / 中心+环复合 | |
| 孔数 | 1–24 | |
| 单孔直径 | 2–40 mm | 建议 ≥ 1.0 mm（0.4 喷嘴的 2.5 倍） |
| 环形半径 | 0–40 mm | 非单孔布局时生效 |

### 壁部导水槽

| 参数 | 范围 | 说明 |
|---|---|---|
| 导水槽形式 | 无 / 螺旋凸肋 / 径向铣槽 | 与杯型不匹配时页面会说明原因 |
| 分段模式 | 整壁统一 / 分段设计 | 分段模式下可逐段设定 |
| 肋/槽数量 | 0–24 条 | |
| 肋宽 / 槽宽 | 0.5–8 mm | **周向**占位宽度 |
| 肋高 / 槽深 | 0.2–4 mm | < 0.8 mm 时滤纸可能压贴，页面会警告 |
| 螺旋圈数 | 0.5–3 圈 | 每条肋绕壁的圈数 |

**分段结构**（仅分段模式）：每段可设 `形状`（螺旋 / 直肋 / 光壁）、`起止高度`、`条数`、`宽度`、`高度`、`圈数`，并提供「下部螺旋·上部直肋」等快速模板。

### 咖啡与冲煮

粉量 6–40 g · 研磨度 0–100 · 粉水比 8–25 g/g · 闷蒸水量 0–6×粉量 · 闷蒸时长 0–120 s · 注水段数 1–6 · 注水总时长 10–240 s · 水温 80–100 ℃

> 这一组参数**不影响几何**，只影响流道模拟 —— 用来验证"这个杯型配这个粉量会怎样"。

## 打印指南

| 项 | 建议 |
|---|---|
| 摆放 | 杯口朝上，底面贴板 z=0 |
| 层高 | 0.16–0.20 mm |
| 壁圈 | ≥ 3（对应模型壁厚 2.4 mm） |
| 材料 | PP（耐热 100 ℃）或 PETG；**PLA 不适合 90 ℃ 以上热水** |
| 支撑 | 锥形杯一般不需要（最大偏离竖直 30°，在 45° 自稳范围内）；平底 / 直筒需自行判断 |

**导水槽的打印方向很关键**：肋约凸出 1 mm，杯口朝上、肋朝内腔，滤纸才会自然压在内壁上形成袋腔 —— 这正是导水槽要泄压的那个腔体。

## 常见问题

<details>
<summary><b>为什么不用 three.js？</b></summary>

为了保证 `index.html` 是**真正的单文件**。用 three.js 就得 CDN 引用（破坏离线能力）或把 600KB 库塞进文件里。
自己写渲染器只要 450 行，还能顺带精确控制 flat shading 与剖切平面的行为 —— 这两点恰好是通用引擎里最麻烦的部分。

</details>

<details>
<summary><b>导水槽的物理模型和几何模型是同一套吗？</b></summary>

**是**，这是刻意的设计。

- 物理侧：肋宽按**周向占位**算（`freeW = 周长 − 条数 × 肋宽`），材料体积按 `Σ 条数 × 宽 × 高 × 路径长` 算
- 几何侧：网格用**等高度水平切片**建，每片占据的周向弧长恰好等于肋宽

如果几何侧改成"沿螺旋路径扫掠垂直于路径的矩形截面"，体积会少 $1/\cos(\text{螺旋角})$ 倍，与物理模型对不上 —— 打印出来会比预期轻，泄压效果也会偏。

</details>

<details>
<summary><b>为什么导水槽要用"分段"？</b></summary>

因为泄压通道沿母线是**串联**的。整壁统一规格时，螺旋肋的泄压路径太长（阻力大）；改成"下部螺旋 + 上部直肋"，直肋段直通杯口，阻力小得多，瓶颈立刻缓解。

代价是：只要有一段是光壁，整条通路就废了 —— 因为串联电路里最弱的一环决定总阻力。所以分段模式的价值在于**精确定位并消除瓶颈段**。

</details>

<details>
<summary><b>导水槽在杯内侧看不见怎么办？</b></summary>

点工具栏的 **「剖切」**（带滑杆，可切开杯身）或 **「半透」**（透外壁）。
分段模式首次启用时会自动打开剖切。另外「几何剖面」页签始终以二维剖面展示内壁结构，不受视角影响。

</details>

<details>
<summary><b>导水槽和杯型不匹配会怎样？</b></summary>

物理模型会直接说明原因，并禁用建出：

- 螺旋凸肋需要**锥壁**才形成袋腔 —— 直筒杯上凸肋无法泄压
- 径向铣槽铣在**底面**上 —— 锥形杯底收束成锥尖，无处可铣

页面会在导水槽诊断面板给出具体说明，不会默默建出一堆没用的几何。

</details>

<details>
<summary><b>能导出给 Bambu Studio 吗？</b></summary>

能。点 **「⬇ 3MF」** 导出，得到的 `.3mf` 是标准 3MF（ZIP + `3D/3dmodel.model` + 正确的 XML 命名空间 + 合法索引范围），可直接拖进 Bambu Studio 切片。

STL 也完全兼容，但不含切片设置（层高、壁圈数需在切片软件里设）。

</details>

<details>
<summary><b>打印出来能用吗？</b></summary>

工具输出的是**设计参考**，不是安全认证产品。使用前请自行验证材质耐热、实际强度（取决于层高、填充率与机器精度），以及形状是否适合你的冲煮习惯。

</details>

```bash
python3 tools/assemble.py -o dist/x.html

# 回归校验（两个都必须全绿）
node tools/check_presets.js
node tools/check_geometry.js
```

### 目录结构

```
├── index.html              # 自包含成品（组装产物，请勿手改）
├── docs/                   # README 配图
├── src/
│   ├── baseline.html       # 基线页面骨架（组装输入）
│   ├── style.css           # 样式
│   └── js/
│       ├── model_base.js   # 物理模型：渗流 / 堰流 / 通道电导 / 分段规格
│       ├── ui_base.js      # 参数面板 / 剖面绘制 / 诊断面板
│       ├── print3.js       # 可打印实体网格：壁壳 / 滤孔 / 螺旋凸肋 / 径向铣槽
│       ├── view3d.js       # 原生 WebGL 渲染器（轨道相机 / 剖切 / flat shading）
│       ├── export.js       # STL / 3MF / OBJ 导出（3MF 内含 ZIP + CRC32）
│       ├── printadvice.js  # 打印工艺评估
│       ├── v3ext.js        # 三维 / 几何剖面 / 打印面板的集成层
│       └── earcut.js       # 第三方：带孔多边形三角化（ISC）
├── tools/
│   ├── assemble.py             # 组装单文件产物
│   ├── check_presets.js        # 6 个预设的网格校验
│   ├── check_geometry.js       # 16 个扩展场景的网格校验
│   ├── smoke_test.js           # 浏览器端冒烟测试（Playwright）
│   ├── validate_exports.py     # 校验导出的 STL / 3MF / OBJ
│   ├── render_offline.js       # 离线软件渲染（无 WebGL 依赖，出 PNG）
│   └── capture_docs.js         # 重新生成 README 配图
└── samples/                # 可直接切片的示例模型
```

### 技术栈

| | |
|---|---|
| 渲染 | 原生 WebGL 1.0（手写矩阵/着色器，flat shading） |
| 几何 | 自研回转壳 + earcut 带孔三角化 |
| 导出 | 手写二进制 STL / ZIP+CRC32 的 3MF / OBJ |
| 依赖 | **零运行时依赖**，无框架、无 CDN、无构建步骤 |
| 运行时 | 任意支持 WebGL 的现代浏览器 |
